# Real-time emulator checks

The optional RT_REGRESSION build runs the C checks on the emulated GBA CPU. The normal ROM contains no regression callback or report memory. Build with `RT_TEST_FLAGS=-DRT_REGRESSION`, forcing `src/main.c` and `src/realtime_battle.c` if switching an existing build. Export symbols with `arm-none-eabi-nm -n pokefirered.elf`. Use `run_regression.py --help` for paths; it requires a local mGBA libretro DLL and Pillow. Rebuild without RT_TEST_FLAGS before playing or distributing the game.

`wild_native.py` tests the production ROM. Pass `--repo` (this source root), `--symbols` (production nm output), `--core` (mGBA libretro DLL), `--battery` and `--output-dir`. Its battery fixture is a disposable normal-game save after the first lab rival battle with a healthy level-5 Bulbasaur carrying Tackle and Growl. It boots Continue, uses RAM-only warps and map fixtures, and writes its states/screenshots/reports only under the requested output directory. It never changes the input battery file. Default structure offsets are for v8. --layout accepts the compiler-exported JSON array gRtTestLayout from the instrumented ROM; regenerate it whenever the structures change.

Cases include real walking encounters, reachable grass, disconnected pockets, a visible detour traversed with D-pad movement and a melee hit, insufficient grass/current-map boundary fallback, START escape during intro/countdown/picker/fight, compact Growl notices and unlocked field movement afterward. The normal-battle fallback is also started and allowed to leave the overworld callback.

`psychic_native.py` accepts the same fixture paths plus `--arm-tools` (the directory containing arm-none-eabi-as.exe and arm-none-eabi-objcopy.exe). It tests native A-button Psychic, one damage event on landing, no damage while lifted, a fast D-pad dodge, ordinary walking, interruption/release, the zoomed Sabrina arena, and escape during a lift. A short Thumb trampoline in unused emulator EWRAM calls native functions for fixture move access, enemy casting and cancellation; it is not a production ROM hook. The input save is never written.


attack_native.py accepts the same paths as psychic_native.py plus --layout. It captures 29 production-ROM cases, including five Flamethrower directions outdoors and in the gym, Hydro Pump, Ice/Hyper/Solar/Psy/Dark beams, projectiles, close hits, ground/area effects and Psychic. Original emulator frames and APNGs are saved to --output-dir; --smoke runs four representative cases. attack_integration.py uses the same arguments for cover, progressive tree destruction, simultaneous private beam matrices, exact streamed VRAM/palette comparisons, repeated mixed-cast resource cleanup and Sunny Solar Beam timing.

The gRtTestLayout array is 29 little-endian u32 values at its exported ROM symbol: structure sizes and offsets in the order declared in tests/realtime_regression.inc.c. It exists only in the instrumented build. Extract its bytes before switching back to production. Native fixture calls can span a video frame; assertions inspect completed objects rather than treating an allocation in progress as a ready sprite. Tests never write the input battery save.


attack_all_moves.py accepts the same fixture arguments and observes an imported effect for each of the 218 mapped damaging moves. Sleep/Stockpile requirements are provided in the fixture. Counter's impact and Bide/Mirror Coat's return projectiles are invoked directly for art coverage; this is not a complete simulation of each move's battle mechanics. All clips/fields are examined, with no need to teach illegal moves to a real save. compiled_art.py --symbols production-nm.txt --output result.json independently checks that every converted sheet/palette and move-art mapping is actually present in the compiled production ROM. tools/build_ptd_emitters.py refreshes the precomputed face positions when the included HGSS sprite sheets change.


status_native.py uses the same fixture paths and --layout as attack_native.py. It observes every status-art row and records real A-button status casts, validates the recipient side, and exports original PNG/APNG captures. C status tests cover reflection/snatching, stage caps/immunity, attached position updates, timed screen expiry, ailment cure, party replacement and tile/palette/matrix cleanup. The status table adds no fields to save data or RtBattle.
